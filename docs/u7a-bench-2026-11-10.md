## Method

- Harness: the old `run-m1-performance-matrix.py` is bound to f42 build provenance checks and to the `tests/base-smoke` fixture world, which no longer exists on disk, and `horizon-offline-test.py` rejects fdc87ae and a build without `native-mods.json` (STOCK). So `bench.py` re-implements the same flow (it is a new script; the old ones are untouched): disposable profile, the 52-pack v3 stack from `outputs/horizon-converter/2026-11-04-Tanush-f42-v3` with its `native-settings-candidate.json` options, the harness graphics file (workers 0, efficient pacing, native, no TAA), 1280x720 window, fps cap 260, vsync off, render distance 12 / sim 8, `horizon-client --control`, `horizon-ctl`.
- World: the fixture was gone, so a seed-0 creative world was generated once with R11 (spawn at -31.5,69,4.5), the old harness flight corridor (-527.5,95,57.5 to -399.5,95,57.5) was pre-generated and saved (template, 20 MB), and each run clones it (`cp -c`) so every run starts from identical saved terrain with no generation work. Runs start at -527.5,95,57.5 looking yaw 0 pitch 15. Numbers are therefore not comparable with the older f42 docs (different scene, no cow fixture).
- Run: launch, wait-ready, wait for 637 columns and quiet streaming, gpu-passes on, front the window, 15 s warmup bench, `bench 15` (static window, "15 s measure"), then `fly` along the corridor for 16 s (the old harness' flight, 10 deg pitch, uncapped). CPU/GPU ms are the in-engine per-frame averages from `bench`/`fly`. Peak RSS is the max of `ps rss` sampled every 1 s from launch to quit. Swap delta is `vm.swapusage` used before launch vs after the static window (the flight delta is in the json as `swap_delta_end_M`).
- Scenarios: `packs` (52 packs, shader off) and `makeup` (same plus `MakeUp-UltraFast-9.6.zip` with its sidecar, from `outputs/horizon-runtime/game/shaderpacks`).
- Order, per scenario: DAILY STOCK R11 R11 STOCK DAILY (ABCCBA) then STOCK R11 DAILY, so 3 runs per build per scenario, each build in varied positions. Per-run gate before launch: idle >= 120 s, no horizon-client or java game, AC, thermal pressure 0, screen unlocked (waited up to 76 s when a gate was transiently not met). 45 s cool-down between runs. Audio muted for runs.
- First MakeUp attempt (run 10, DAILY) presented only 13.2 of 16 flight seconds (26.4 FPS static) and my strict 15 s check flagged it; that json is kept as `runs/_invalid-first-attempt-a-10-makeup-DAILY.json.txt`. I relaxed the flight check to >= 10 s presented, and the rerun of run 10 presented the full 16 s. All 18 runs in the table are valid and presented full windows; nothing was below 15 FPS.
- Noise band: spread (max-min) of per-run avg FPS within a build: shader off 0.5-2.0 FPS (static) / 0.5-1.5 (flight); MakeUp 0.1-0.7 FPS. 1% low spreads are larger (shader off up to 5 FPS, MakeUp up to 0.7). A difference counts as real only when it exceeds both builds' spreads. n=3 is small; the spreads are minimum estimates.
- Swap: used swap stayed near 830-900 MB and did not grow during any run (deltas 0 to -24 MB), so swap did not contaminate results here (unlike the earlier docs' 2.5-3 GB).
