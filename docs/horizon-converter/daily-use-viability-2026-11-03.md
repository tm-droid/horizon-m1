## World/save facts and preservation limits

f42 pins Minecraft26.3, protocol777 and world DataVersion5023. Its save module writes Java26.3 Anvil regions, separate entity regions and the newer26.3 paths: `players/data/<uuid>.dat`; `dimensions/minecraft/<dimension>/region/`; and `data/minecraft/` saved-data files. `level.dat` retains `singleplayer_uuid`. Legacy layouts are migrated on opening. Therefore do not judge compatibility using only pre26.3 `region/`, `DIM-1/` and `playerdata/` expectations. [Pinned version constants](https://github.com/horizon-rust/horizon/blob/f42ef42ef6ceccb3c6a20bea2481d87949a51c81/crates/horizon-core/src/version.rs), [save format contract](https://github.com/horizon-rust/horizon/blob/f42ef42ef6ceccb3c6a20bea2481d87949a51c81/crates/horizon-client/src/save.rs#L1).

Older saves are actively upgraded: file fixes/level.dat, then chunks, entity regions, POI, player files, saved data, statistics and advancements. Horizon upgrades the world on open rather than merely inspecting it; version5023 files can also contain older records upgraded on read. The session lock prevents simultaneous use, but it is not a rollback mechanism. An ordinary load/save changes ticks, entities, inventories and other gameplay state even if storage is compatible. [Upgrade entry point](https://github.com/horizon-rust/horizon/blob/f42ef42ef6ceccb3c6a20bea2481d87949a51c81/crates/horizon-client/src/save.rs#L183).

The source retains loaded unknown entity/block-entity/root fields where supported and merges known state back. **That does not make arbitrary Fabric worlds safe:** `decode_column` resolves each block palette against the available registry and falls back to air when no registered state/default exists; sections outside the selected layout are skipped. Unknown structures/payload preservation is not execution of their Java code. Any world with custom blocks/dimensions/data-driven registries requires those registrations and heights to be verified before it is opened in Horizon, even as a clone. The user's installed client mods may be mostly cosmetic, but this audit did not inspect their actual world contents and must not assume vanilla-only saves. [Exact block-palette fallback](https://github.com/horizon-rust/horizon/blob/f42ef42ef6ceccb3c6a20bea2481d87949a51c81/crates/horizon-client/src/save.rs#L1655).

For later round-trip acceptance, capture known landmarks and representative block states, block entities/container contents, player inventory/ender chest/effects/UUID/position, pets and passengers, scheduled ticks, advancements/stats, POI and dimension data. Use normal clean save/quit between clients, never two instances on this8GB machine. Reopen a second independent copy in Java26.3; raw hashes of rewritten save files are not expected to match, so compare decoded semantics and visually inspect the fixtures. Never overwrite the Java source world with the test result. This audit did not run that check.

### Backup versus export

The launcher's world backup locks the world and archives every file except `session.lock`; world copy recursively copies the files, excludes the lock and renames `LevelName`. Those are the appropriate preservation-oriented paths, subject to independently checking the produced archive/copy before use. [Pinned backup/copy implementation](https://github.com/horizon-rust/horizon/blob/f42ef42ef6ceccb3c6a20bea2481d87949a51c81/launcher/src/worlds.rs#L162).

`instance export` intentionally shares an instance: fixed settings/pack/mod folders, selected worlds, no logs/caches/backups, and a per-world exclusion list of `playerdata`, `stats`, `advancements`, `session.lock`; it removes `Data.Player.UUID` from `level.dat`. This is not a full recovery archive. **Specific f42 gap:** that exclusion/redaction code does not cover the actual26.3 `players/data/` directory or `Data.singleplayer_uuid`, so its privacy claim cannot be assumed for the new layout. It also excludes dotfiles. Do not publish a world export based on the description alone; no export/publication was attempted here. [Exact export lists](https://github.com/horizon-rust/horizon/blob/f42ef42ef6ceccb3c6a20bea2481d87949a51c81/launcher/src/export.rs#L21), [redaction function](https://github.com/horizon-rust/horizon/blob/f42ef42ef6ceccb3c6a20bea2481d87949a51c81/launcher/src/export.rs#L203).

## Older servers: actual adapter boundary

The code has a real native packet adapter, not simply a changed advertised game version. `ServerVersion::ALL` supports current26.3,26.2,26.1/26.1.1/26.1.2 and1.21.11. Their protocol IDs are777/776/775/774. No entry exists here for1.21.10 and earlier,1.20.x or1.8. This list cannot replace ViaFabricPlus's broader version support. [Exact enum and mappings](https://github.com/horizon-rust/horizon/blob/f42ef42ef6ceccb3c6a20bea2481d87949a51c81/crates/horizon-protocol/src/adapter.rs#L25).

Furthermore f42 `net::older_servers_enabled` is **off by default while the adapter is incomplete**; `HORIZON_OLDER_SERVERS=1` opts into a status ping and recognized protocol selection. Unknown protocol/failed ping returns no older-version selection. Packet IDs, embedded registry IDs and changed layouts have translation paths, but unknown packets may be dropped and translation failures can log and pass the original payload to the normal reader. These are source capabilities, not proven server compatibility. No live connection was made. [Feature gate/autodetection](https://github.com/horizon-rust/horizon/blob/f42ef42ef6ceccb3c6a20bea2481d87949a51c81/crates/horizon-client/src/net.rs#L562), [translation failure behavior](https://github.com/horizon-rust/horizon/blob/f42ef42ef6ceccb3c6a20bea2481d87949a51c81/crates/horizon-protocol/src/adapter/session.rs#L84).

Before enabling daily multiplayer, later tests need login/configuration, chunk/world registry decoding, inventory/crafting, movement/collision, combat, dimension changes, chat/resource packs, reconnect and any required plugin channels. Server-side ViaVersion may separately accept a26.3 client, but that is endpoint-specific and cannot be inferred here. Offline local test success also says nothing about an online server's account/session requirements; no bypass is proposed.
