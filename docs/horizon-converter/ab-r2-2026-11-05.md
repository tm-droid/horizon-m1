# A/B: Horizon native r2 candidate vs control (2026-11-05/06)

Candidate `native-f42-m1-r2-e7f5b3e786b6` vs control `native-f42-m1-control-09391c2a8210`, M1 Air 8 GB, AC power.

## Method
- Runner: `outputs/horizon-runtime/run-m1-performance-matrix.py` (backup `.bak-u6b`), tag `u6ab`, 16 runs, 8 per case (4 per build), ABBA + BAAB interleaved, fps cap 260 (uncapped in practice), scene cow, migration v3, 1280x720 (runner default; not 2560x1440), warmup 15 s, static 20 s + flight 16 s per run.
- Cases: `makeup` = MakeUp-UltraFast-9.6 shader; `packs` = shader-off with the 52 resource packs (the runner's shader-off case).
- Runner edits: thermal gate (pmset therm), 60 s cooldown between runs, swap delta per run, fixed a provenance compare that broke when the control was reused (setdefault of built_control_sha256).
- Gates every run: AC, unlocked, no cargo/rustc/xcodebuild/PineconeMC, >=4 GiB free. Runs went through device-testing-queue.
- Analysis: `analyze-ab-u6b.py`; consecutive runs form a (control, candidate) pair, so 4 pairs per case. Median of paired deltas, 10k-resample bootstrap 95% CI. Verdict: CI excludes 0 -> WIN/REGRESSION, else NO EFFECT. With only 4 pairs the CIs are narrow-looking but fragile.
- Smoke: no WGSL, naga, wgpu validation or panic lines in any candidate log (shader-off and MakeUp). MakeUp scene diff candidate vs control (94.9% any-pixel) equals control vs control (96.1%): animated scene, so not a regression signal. Shader-off diff 3.6% vs 3.3% baseline.
