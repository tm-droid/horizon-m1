# macOS Game Mode for the Horizon client (2026-11-05)

## Verdict
- Bare `launcher-data/versions/<v>/horizon-client` (what the harness runs, and what the launcher is believed to spawn; launcher spawn path not directly observed) is NOT labeled a game: gamepolicyd logged nothing for it (bare-2.log), so Game Mode never activates.
- Same binary as the executable of a minimal .app with `LSApplicationCategoryType=public.app-category.games` + `GCSupportsGameMode`/`LSSupportsGameMode` = true: gamepolicyd logs `Found game ... labelReason=LSSupportsGameMode (Info.plist)`, then `Game mode enabled.` and GamePolicyAgent `Posted game mode enabled notification.` (wrap-1.log) when fullscreen and focused.
- Windowed (1280x720) wrapper: labeled but stays `Game mode status is now off` (wrap-win-1.log). Fullscreen is required.

## Criteria and sources
- Keys: GCSupportsGameMode (macOS 14+), LSSupportsGameMode (macOS 26+), LSApplicationCategoryType games; eligibility only, OS decides; auto-disabled when not fullscreen. Apple Developer Forums threads 782343 (How to Enable Game Mode), 764575 (What triggers Game Mode?); page fetch blocked by bot check, content via search summary.
- Child/unbundled processes: Apple forums 787702 (Java child window fullscreen did not activate); Cellar issue 46 https://github.com/Echarnus/Cellar/issues/46 (bare wine, no bundle, no category).
- Measured table (copied loader into bundle works; bare or no-category bundle does not; needs input focus + display-covering window): https://github.com/gauthierpiarrette/highball/issues/338
- Detection: `/usr/bin/log stream --predicate 'process == "gamepolicyd"'` (also GamePolicyAgent). Messages undocumented. https://github.com/rocavence/Gamely-app/blob/main/README.en.md . Note: in zsh use `/usr/bin/log`, the builtin `log` shadows it.
- Cannot be forced for windowed apps by any key found.

## Fix (prototype only, nothing existing modified)
`outputs/horizon-runtime/gamemode-wrapper/Horizon GM.app`: Info.plist (id dev.horizonlab.gamemodeclient, games category, both Game Mode keys) + `Contents/MacOS/horizon-client` = `cp -c` APFS clone of the version binary, ad-hoc `codesign --force --sign -`, `lsregister -f`.
Integration (not done): launcher must exec the clone inside the bundle (with the same `--resources` args; it needs no sibling files), or `open`-less exec of `Contents/MacOS/horizon-client` per version; re-clone on every version install/update. Player must run fullscreen (`--fullscreen`) for it to turn on. Visuals/settings unchanged.
Files: probe.sh (log capture), ab.sh, horizon-offline-test-gm.py (harness copy; HGM_EXE / HGM_FULLSCREEN env), out/*.

Conclusion: no measurable avg-FPS change (+0.2, inside noise); B slightly better 1% low / p99 (+0.6 fps, -1.4 ms stationary), within the run-to-run spread (A runs spanned 36.9-41.1). Caveats: heavy swap (2.7-3.1 GB used) and ±3 fps noise per bench-method doc; run 1 (A1) had the highest FPS and 3 GB swap total vs 4 GB later; 4 runs/arm is too few for the tail metrics. Game Mode's expected gains (background CPU/GPU priority, Bluetooth rate) are not what this harness measures.
