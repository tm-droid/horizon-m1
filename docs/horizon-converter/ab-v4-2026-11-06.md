# A/B: resource migration v4 vs v3, 2026-11-06

Verdict: keep v4 as the daily migration. No regression found; packs shader-off static FPS is higher in v4, MakeUp is unchanged. v4-strict was not run (reasons below).

## Setup
- Control native build `native-f42-m1-control-09391c2a8210` for every run, runtime `nightly-2026-11-03-f42ef42`, so only `--migration` differs. Harness `tools/horizon-offline-test.py` already has `--migration`; it was not modified.
- v3 = `outputs/horizon-converter/2026-11-04-Tanush-f42-v3`, v4 = `2026-11-05-Tanush-f42-v4`.
- Cases: `packs` (shader off) and `makeup` (MakeUp 9.6). Each run: cow scene, 2560x1440 surface, RD 12 / sim 8, cap 260, VSync off, warmup 15 s, static 20 s, flight 16 s (same flags as the cloud/shadow A/B).
- 4 valid runs per arm per case, ABBA then BAAB order: packs v3 v4 v4 v3 | v4 v3 v3 v4, then the same for makeup. 16 runs, all valid, none tainted, Horizon frontmost in all.
- Runner `outputs/horizon-runtime/ab-v4/run-ab-v4.py`, analyzer `analyze-ab-v4.py`, raw per-run records and screenshots in `outputs/horizon-runtime/ab-v4/data/<label>/`. Runs 3 to 16 ran as one queue job with a 60 s cooldown between runs.
- Gates in the queue turn: AC power, screen unlocked and display awake, no cargo/rustc/xcodebuild, no PineconeMC or horizon-client, at least 4 GiB disk. Memory pressure, thermal pressure and swap were recorded per run but not enforced inside the single queue job.
- Stats: median per arm, bootstrap 95% CI (10,000 resamples) on the difference of run-level medians. With n=4 per arm these CIs are optimistic.

## Caveats
- Thermal pressure level was 1 (sometimes 2) for all runs after the first, per `notifyutil com.apple.system.thermalpressurelevel`. ABBA interleaving spreads this over both arms, but absolute FPS is probably lower than a cold machine would give.
- Swap was 2.9 to 3.4 GB used the whole time. Memory free was 56 to 62% at run start.
- Packs shader-off at 150 to 170 FPS is CPU/present-bound and the noisiest case (see `bench-method-and-shader-options-2026-11-05.md`). I have no mechanism that explains why 3,473 fewer files would raise static FPS by 7%; treat the packs gain as "no regression, possible small gain" until repeated.
- Startup times in the packs case have outliers (full-scene time up to 39 s for v3 and 50 s for v4) that look like contention from other agents' queue jobs.

## v4-strict
Not run. v4 is at least as fast as v3, but strict drops 12,057 files by a file-level static graph. Its own doc warns that a missed reference shows up as a missing-model purple cube, and the benefit is only 5 more emissive pairs. I have no evidence that strict is look-neutral, so it is not worth queue time yet. If someone wants it, `run-ab-v4.py batch --phase strict` runs v3, v4s, v4s, v3 per case.

## Recommendation
Use v4 for daily play. Keep v3 as the fallback. The remaining open item is a visual ore-glow check in a cave scene.
