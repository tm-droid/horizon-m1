# U20: r3 vs QoS-less r3 bisect (2026-11-06)

## Question
r2 showed a MakeUp static p99 regression vs control (+3.47 ms, 4/4 pairs, shrinking per round). U19 suspected the
thread-QoS transforms (`qos-backport-f42`, `jobpool-qos-f42`). This bisect builds r3 without them
(`native-f42-m1-r3noqos-539e0dc80527`, `build-m1-performance-r3noqos.py`) and runs paired rounds.

## Setup
- Builds: control `native-f42-m1-control-09391c2a8210`, r2 `native-f42-m1-r2-e7f5b3e786b6`,
  r3 `native-f42-m1-r3-6b039bd4b49f`, r3noqos `native-f42-m1-r3noqos-539e0dc80527`.
- Runner `outputs/horizon-runtime/run-r3-bisect.py` (batched, one queue job), analyzer `analyze-r3-bisect.py`.
  Raw: `outputs/horizon-runtime/r3-bisect-r3b.json`, tables `r3-bisect-r3b.tables.md`.
- 1280x720, fps-cap 260, scene cow, `--flight`, migration v3, 60 s cooldown, gates (AC, unlocked, no builds, no Java MC).
- 24 of 27 planned runs, all valid, all on AC. MakeUp round 5 (3 runs) was not run: the user paused the job at
  06:26 and then left without a charger. Analysis uses 4 paired rounds per case.

## Verdict
- **QoS is not the cause of the MakeUp p99 tail.** Removing it makes MakeUp static worse: 1% low -5.6 FPS and
  CPU p99 +9 ms vs control (both CIs exclude 0, 4/4 rounds). The QoS transforms stay.
- **r3 vs control on MakeUp:** p99 +1.8 ms with a CI that includes 0 (r2 was +3.47 ms, CI excluding 0). Average
  and flight are unchanged. The residual tail is unproven and small. Its source is not the QoS code; the r2 rounds
  shrank from +5.4 to +2.0 ms, which points at an order/warm-up effect as much as at a patch.
- **r3 vs r2 shader-off:** static 1% low +8.4 FPS (4/4), average and flight within noise.
- **Daily build: r3 `native-f42-m1-r3-6b039bd4b49f`.** r3noqos is rejected.
