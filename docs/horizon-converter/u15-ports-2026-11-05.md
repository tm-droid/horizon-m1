## Design notes
- particle-cull: `render` -> wrapper over `render_in_view(.., in_view, ..)`; per-particle box `center +- (1.5*|size|+0.05)` against `Game.view_frustum` (the far plane is the distance cull; no extra distance cap, to keep zero visual change). Skipped when a native shader pack is picked (its shadow pass reads the same entity buffer). Simulation untouched; kept quads keep order, so translucent layering is unchanged.
- adaptive-upload: appended `mod adaptive_upload` in game.rs (no new files, so r2's `NEW_FILES` guard passes; no new setting keys). Factor in [1,2] scales `chunk_updates`, `upload_budget_kib` and the unbudgeted 2/6 ms slice. Inputs: max(CPU,GPU) frame ms from the `record_cpu` spot, centre-chunk stillness (20 updates -> 2.0), backlog growth (floor 1.5 for 10 updates). Never below 1 so settle cannot regress by construction (the failed fixed-512 KiB case is the opposite design). Kill switch `HORIZON_ADAPTIVE_UPLOAD=0`.
- Honest limit: because the floor is r2's allowance, adaptive-upload mainly speeds fill-in when frames are cheap; it will not by itself remove an r2 upload spike. If 1% lows are the target, A/B also with lower base `chunkUpdates`/`uploadBudgetKiB` plus this on.

## Add to an r3 build script
1. `cp outputs/horizon-runtime/build-m1-performance-r2.py outputs/horizon-runtime/build-m1-performance-r3.py` (leave r2 alone).
2. In r3: `LAB = RUNTIME / "m1-performance-r3"`; update the docstring.
3. `PERF_MODS = [... r2 list ..., "particle-cull-f42", "adaptive-upload-f42"]` (append at the end; both only need game.rs anchors from r2 output; order between them is free).
4. Nothing else: `expected` is built from `mod.FILES` automatically (adds `particles.rs`; game.rs is already in r2's set). Both mods have `REVISION` = f42ef42... and `NEW_FILES = {}`, as the loop requires.
5. SOURCE for r3 is still the pristine `launcher-data/native/stage` (r3 re-applies cloud-prep, shadow-scratch and all PERF_MODS), so each `render()` sees r2's output for game.rs: matches the reviewed `base_sha256`, which enforces the reviewed output hash.
6. After the build: cargo check/test as in each build-plan.json, then bench (idle, flight route 1% lows, post-flight settle vs r2 4.17 s, a particle-heavy scene). A/B adaptive in-binary with `HORIZON_ADAPTIVE_UPLOAD=0`.
