# Horizon tune for MacBook Air M1 8 GB (2026-11-12)

Build: `native-fdc87ae-m1-daily7-73decc0fdc30` (unchanged). Player setup: MakeUp-UltraFast-9.6 + tierA sidecar,
resolutionScale 85, render distance 12, simulation 8, 64 resource packs, fullscreen 2880x1800.

Method: `outputs/bench-2026-11-10/real.py` copies the player's own options, graphics settings, shader and every
enabled pack into a throwaway profile on the bench world, launches fullscreen, and measures a 15 s static bench,
a scripted flight, and `phys_footprint` (the real memory cost on Apple silicon; RSS hides compressed and GPU memory).
Static numbers are avg fps / 1% low with maxFps 260.

## Where the memory goes
- Game footprint ~3.4 GB, of which ~3.1 GB is graphics (IOAccelerator + GPU-owned buffers).
- On 8 GB, the game plus the Claude app (~0.8 GB) and the browser push macOS into swap. That caused the stutter
  in the 19-minute server session (swap 1.5 -> 2.9 GB, p99 136 ms), more than any game setting.
- Packs cost 1.3 GB and 13 fps in total (all packs off: 59.4 fps, 2.15 GB).

- `Dramatic Skys M1.zip` replaces `Dramatic Skys Demo 1.5.3.36.6.zip` in the pack list: sun/moon/skybox textures

## Presets: `tools/horizon-perf.sh` (game must be closed)
- `pretty`: your normal setup.
- `fast`: Optimized Bushy Leaves off. Measured 58.8 fps / 3.07 GB vs 46.5 / 3.40 GB.
- `max`: fast + resolutionScale 70 + render distance 10.
- `status`: shows the current mode. `pretty` restores the exact saved values (round trip is byte-identical).

## Bench fix
daily7 ships `dynamic-fps-for-rust`, which caps a focused window to 20 fps after 60 s without input. Hands-free
flights hit it (frames capped at 50 ms), so earlier flight numbers, including the U5 upload-budget flight win, are
unreliable. `bench.py` and `real.py` now write `config/dynamic-fps-for-rust.json` = `{"enabled": false}` into each
bench profile. Normal play is unaffected (you give input), and the idle cap saves power when AFK.
